# Runbook — Deploy to AWS EU (Frankfurt)

Deploys the container images on **ECS Fargate** in `eu-central-1` with the Terraform in
[`infra/terraform`](../../infra/terraform). Honors the non-negotiables: EU residency, TLS,
KMS-at-rest, WORM documents, RLS role separation, secrets from a vault (CLAUDE.md §2/§7/§11).

> This stack has not been `terraform apply`-tested in this repo (no AWS at authoring time).
> Run `terraform plan` and review before every `apply`.

## 0. Prerequisites
- AWS account; admin credentials for the first apply (`aws sts get-caller-identity` works).
- Tools: `terraform >= 1.5`, `aws` CLI, `docker` (with buildx).
- A **domain** + an **ACM certificate in `eu-central-1`** covering `api.<domain>` and `app.<domain>`.
- A remote state backend (S3 + DynamoDB lock) — uncomment the `backend "s3"` block in `versions.tf`.
- **Read [`infra/terraform/README.md`](../../infra/terraform/README.md) → the `BYPASSRLS` blocker** and pick a DB path.
  For an immediate compliant deploy set `use_rds = false` (self-managed Postgres on EC2).

## 1. Provision infrastructure
```bash
cd infra/terraform
cp terraform.tfvars.example terraform.tfvars   # edit: domain, acm arn, use_rds, google_client_id
terraform init
terraform plan -out tf.plan                    # REVIEW carefully
terraform apply tf.plan
```
This creates: VPC, RDS/EC2 Postgres, ElastiCache Redis, S3 (WORM), ECR repos, Secrets Manager
entries, ALB, ECS cluster, task definitions, and services. Services stay **unhealthy until images
exist** (next step) — that's expected.

> **If `use_rds = false`:** bootstrap the EC2 instance now — install PostgreSQL 16 on the encrypted
> `/dev/xvdf` volume, create the `accounting` DB and the master/owner role **as a SUPERUSER**
> (required so migration `0006` can grant `auth_lookup BYPASSRLS`), enable TLS, and set its password
> to the `db/master_password` secret value. Then continue.

## 2. Build & push images to ECR
```bash
ACCT=$(aws sts get-caller-identity --query Account --output text)
REGION=eu-central-1
aws ecr get-login-password --region $REGION | docker login --username AWS --password-stdin $ACCT.dkr.ecr.$REGION.amazonaws.com

API=$(terraform output -raw -state=infra/terraform/terraform.tfstate ... )   # or read from `terraform output ecr_repository_urls`
# Using the outputs map:
API_REPO=$(terraform -chdir=infra/terraform output -json ecr_repository_urls | jq -r .api)
WEB_REPO=$(terraform -chdir=infra/terraform output -json ecr_repository_urls | jq -r .web)
WORKER_REPO=$(terraform -chdir=infra/terraform output -json ecr_repository_urls | jq -r .worker)
APP_ORIGIN=$(terraform -chdir=infra/terraform output -json public_origins | jq -r .app)
API_ORIGIN=$(terraform -chdir=infra/terraform output -json public_origins | jq -r .api)

# api + worker (same source, different entrypoints)
docker build -f infra/Dockerfile.api    -t $API_REPO:latest    . && docker push $API_REPO:latest
docker build -f infra/Dockerfile.worker -t $WORKER_REPO:latest . && docker push $WORKER_REPO:latest

# web — NEXT_PUBLIC_API_URL is baked in at build time; point it at the API origin
docker build -f infra/Dockerfile.web --build-arg NEXT_PUBLIC_API_URL=$API_ORIGIN \
  -t $WEB_REPO:latest . && docker push $WEB_REPO:latest
```

## 3. Set the secrets that aren't auto-generated
`db_master`, `db_app_user`, and `jwt` are generated by Terraform. Set the Google secret out-of-band:
```bash
aws secretsmanager put-secret-value \
  --secret-id mgi-delta-prod/auth/google_client_secret \
  --secret-string 'GOCSPX-...'
```

## 4. Run migrations
```bash
CLUSTER=$(terraform -chdir=infra/terraform output -raw ecs_cluster)
SUBNETS=$(terraform -chdir=infra/terraform output -json private_subnet_ids | jq -r 'join(",")')
SG=$(terraform -chdir=infra/terraform output -raw app_security_group_id)

aws ecs run-task --cluster $CLUSTER --launch-type FARGATE \
  --task-definition mgi-delta-prod-migrate \
  --network-configuration "awsvpcConfiguration={subnets=[$SUBNETS],securityGroups=[$SG],assignPublicIp=DISABLED}"
# watch the /ecs/mgi-delta-prod/migrate log group → "migrations complete"
```

## 5. Set the `app_user` password (required once)
Migration `0001` creates `app_user` **without a password** (by design — set from the vault). Apply the
generated `db_app_user` secret as its password, connecting as the master/owner role. One-off task using
the api image's bundled `pg`:
```bash
APP_PW=$(aws secretsmanager get-secret-value --secret-id mgi-delta-prod/db/app_user_password --query SecretString --output text)
# Run a one-off Fargate task overriding the command (master creds injected as MIGRATION_PASSWORD):
aws ecs run-task --cluster $CLUSTER --launch-type FARGATE \
  --task-definition mgi-delta-prod-migrate \
  --network-configuration "awsvpcConfiguration={subnets=[$SUBNETS],securityGroups=[$SG],assignPublicIp=DISABLED}" \
  --overrides '{"containerOverrides":[{"name":"migrate","command":["node","-e","const{Client}=require(\"pg\");(async()=>{const c=new Client({host:process.env.PGHOST,user:process.env.MIGRATION_USER,password:process.env.MIGRATION_PASSWORD,database:process.env.PGDATABASE});await c.connect();await c.query(`ALTER ROLE app_user LOGIN PASSWORD ${JSON.stringify(process.env.APP_PW)}`);await c.end();console.log(\"app_user password set\")})()"],"environment":[{"name":"APP_PW","value":"'"$APP_PW"'"}]}]}'
```
(Alternatively run the `ALTER ROLE app_user PASSWORD '...'` from a bastion/psql — whatever your ops
prefers. The value must equal the `db_app_user` secret, which the api/worker tasks read at runtime.)

## 6. Start the services
```bash
for s in api worker web; do
  aws ecs update-service --cluster $CLUSTER --service $s --force-new-deployment >/dev/null
done
```
Wait for `api` and `web` target groups to report **healthy** in the ALB.

## 7. DNS + TLS
- Create alias/CNAME records: `app.<domain>` and `api.<domain>` → the `alb_dns_name` output.
- Confirm the ACM cert is validated and attached to the HTTPS listener.

## 8. Google OAuth (production redirect)
In Google Cloud Console → Credentials → your OAuth client:
- **Authorized redirect URI:** `https://api.<domain>/auth/google/callback`
- **Authorized JavaScript origin:** `https://app.<domain>`
- Move the consent screen out of "Testing" (publish) or keep test users listed.
These must match `GOOGLE_REDIRECT_URI` / `WEB_APP_URL` (set automatically from your domain in `ecs.tf`).

## 9. Smoke test
```bash
curl -fsS https://api.<domain>/health/ready
curl -fsS https://api.<domain>/auth/config            # {"googleEnabled":true}
# Browser: https://app.<domain> → register, login, "Continue with Google".
```

## Notes / not yet wired
- **OCR:** `OCR_VENDOR_URL`/`OCR_VENDOR_KEY` are unset → the app uses the deterministic dev OCR. Before
  enabling real OCR, point at an **approved EU, zero-retention** Document-AI endpoint (CLAUDE.md §2.7/§10)
  and add the values as secrets + task env.
- **Email:** set `RESEND_API_KEY` or SMTP_* (as secrets) for invoice delivery; otherwise dev-log sender.
- **Redis TLS:** `REDIS_URL` uses `rediss://` (transit encryption is on). Ensure the ioredis client
  negotiates TLS (the `rediss://` scheme enables it).
- **Backups/DR, WAF, autoscaling, alarms:** add per CLAUDE.md §17 before go-live (out of scope here).

## Rollback
- App: `aws ecs update-service --service api --task-definition <previous-revision>` (or redeploy a prior `image_tag`).
- Infra: `terraform apply` a reverted plan. RDS has `deletion_protection = true`; the documents bucket
  is **WORM** — objects cannot be deleted before retention expiry (by design).
